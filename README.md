# NEON TASKS ✦

Личный планировщик задач в киберпанк-стиле. Работает с телефона и компьютера, сохраняет задачи каждого логина отдельно.

**Что умеет:**

- Регистрация и вход **только по логину**, без пароля.
- Быстрый ввод задач: напишите название и нажмите Enter.
- Галочки выполнения, возврат в работу, изменение и удаление задач.
- Категории (личное, работа, учёба, идеи, покупки + собственные), приоритет и срок.
- Поиск, сортировка, фильтры: сегодня, предстоящие, выполненные.
- Статистика прогресса и адаптивный интерфейс под телефон.
- Хранение задач в Upstash Redis: данные не исчезают после перезагрузки Vercel и доступны с разных устройств при входе под тем же логином.

## ⚠️ Обязательно прочитайте о безопасности

Вход по одному логину **не является защищённой авторизацией**. Любой человек, знающий или угадавший логин, может войти в чужой аккаунт, просмотреть, изменить и удалить его задачи. Это сделано **точно согласно запрошенной модели входа**. Не храните конфиденциальную информацию. Для приватных аккаунтов понадобится хотя бы пароль, одноразовый код или вход через Google.

База Redis и ключ подписи сессий находятся **только на сервере** — они не должны попадать в GitHub или исходный код браузера.

## Вариант 1. Запуск на компьютере (без облачной базы)

Понадобится [Node.js](https://nodejs.org/) версии 20 или новее.

1. Распакуйте архив.
2. Откройте терминал (PowerShell) в папке `neon-tasks`.
3. Запустите:

   ```bash
   npm run dev
   ```

4. Откройте **http://localhost:3000**.
5. Нажмите «Регистрация», придумайте любой свободный логин от 3 до 24 символов.

**Важно:** без переменных среды локальная версия использует файл `.data/dev.json` — он создаётся автоматически, не отправляется на GitHub. При развёртывании на Vercel для хранения задач **обязательна Upstash Redis**, иначе сервер сообщит об ошибке настроек. Файловое хранение нельзя использовать в Vercel: данные там непостоянные.

**Никаких `npm install`, сборки фронтенда и дополнительных библиотек для локального запуска не требуется.**

## Вариант 2. GitHub → Vercel (с облачной базой)

### Шаг 1. Создайте базу Upstash Redis

1. Откройте **https://console.upstash.com/** и зарегистрируйтесь.
2. Создайте новую Redis database (для личного проекта обычно достаточно бесплатного тарифа, если он доступен).
3. В разделе **REST API / REST** скопируйте **REST URL** и **REST TOKEN (не readonly)**.
4. Сохраните эти два значения для шага 3. **Никому не присылайте токен и не добавляйте его в GitHub.**

Официальная инструкция: https://upstash.com/docs/redis/features/restapi

### Шаг 2. Загрузите исходники на GitHub

1. Создайте **пустой репозиторий** на https://github.com/new (например `neon-tasks`).
2. Загрузите **содержимое** распакованной папки `neon-tasks` в корень репозитория: `index.html`, `styles.css`, `app.js`, `api/`, `lib/`, `assets/`, `package.json`, `vercel.json`, `README.md` и остальные файлы. Можно воспользоваться **Add file → Upload files** или GitHub Desktop.
3. Не публикуйте `.env` и `.data/`: они уже прописаны в `.gitignore`.

Или используйте команды Git, если знакомы с ними:

```bash
git init
git add .
git commit -m "Initial NEON TASKS"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/neon-tasks.git
git push -u origin main
```

### Шаг 3. Подключите проект в Vercel

1. Откройте **https://vercel.com/new** и выберите **Import Git Repository**.
2. Выберите созданный репозиторий.
3. **Framework Preset: Other** (конфигурация уже закреплена в `vercel.json`).
4. **Root Directory:** `./` (корень репозитория). Не задавайте отдельную папку сборки; `index.html` лежит в корне.
5. В **Environment Variables** добавьте **три** переменные:

   | Name | Value |
   |---|---|
   | `UPSTASH_REDIS_REST_URL` | REST URL из Upstash |
   | `UPSTASH_REDIS_REST_TOKEN` | REST Token из Upstash |
   | `SESSION_SECRET` | Ваш уникальный случайный секрет **от 32 символов** |

   **Как получить SESSION_SECRET:** откройте локальный терминал с Node.js и выполните:

   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```

   Скопируйте выведенную строку в `SESSION_SECRET`. Никому её не показывайте.
6. Нажмите **Deploy**. Дождитесь публикации и откройте адрес вида `https://neon-tasks-xxx.vercel.app`.
7. Нажмите **Регистрация**, задайте логин. После этого входите с телефона или другого ПК тем же логином — задачи будут общими для этого логина.

Если настройки базы вводились **после первой публикации**, откройте Vercel → Project → Deployments → меню последнего деплоя → **Redeploy**.

### Что происходит при изменении файлов?

Измените код → сделайте commit и push в GitHub. Vercel автоматически обновит сайт. В Upstash останутся все данные пользователей и задачи, даже если вы измените дизайн или перезапустите сайт.

## Структура проекта

```text
neon-tasks/
├── index.html              # Вход, регистрация и интерфейс
├── styles.css              # Дизайн и адаптивность
├── app.js                  # Логика приложения в браузере
├── assets/favicon.svg      # Иконка
├── manifest.webmanifest    # Установка на домашний экран
├── api/
│   ├── auth.js             # Регистрация / вход / выход
│   ├── me.js               # Текущая сессия
│   └── tasks.js            # Создание, чтение, изменение, удаление задач
├── lib/
│   ├── http.js             # Cookie-сессия и HTTP-утилиты
│   └── store.js            # Upstash Redis + локальный режим
├── dev-server.js           # Локальный сервер без зависимостей
├── vercel.json             # Конфигурация Vercel
├── package.json
├── .gitignore
└── .env.example            # Только пример, без реальных токенов
```

**Технологии:** HTML, CSS, JavaScript, Node.js (ES Modules), Web-standard Vercel Functions, Upstash Redis REST API. Нет внешних npm-зависимостей и нет команды сборки.

## Примечания

- Задачи хранятся **у конкретного логина**. Если создать другой логин, список будет пустым и независимым.
- Если задача не сохраняется на Vercel, проверьте 3 переменные окружения и логи функций `api/tasks`.
- Если при регистрации получаете «логин занят» — он уже существует; переключитесь на **Вход**.
- Если потеряли логин, восстановить его без дополнительных данных не получится. Держите его в памяти.
- Сессия хранится в HttpOnly-cookie на 30 дней. Выход очищает cookie текущего браузера, но не удаляет аккаунт/задачи.
- Хранение кода на GitHub не равно размещению сайта: адрес для доступа появится после деплоя в Vercel.
